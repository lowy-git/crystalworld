## 2. 数据流（与规格文档 §C 一致）

```
晶胞 (a,b,c,α,β,γ) → 直基 A,B,C → 倒易基 A*,B*,C*
(hkl) → n = hA*+kB*+lC* → 单位法线 n̂，面距 d = 1/|n|
点群 3×3 正交矩阵 → 把 n̂ 铺成面族 {n̂ᵢ}
多面体 = ∩ {x : n̂ᵢ·x ≤ kᵢ·d}   ← 三元面交点 + 可行性筛选 + 按面归并顶点环 + 棱去重
校验：欧拉 V − E + F = 2
```

## 4. 踩到的三个坑（都已写进代码注释）

1. **教材 74°55′ 的指数是 {10-14}，不是 {10-11}。** 4 指数 {10-11} → 3 指数 (101)，算出 65.82°；4 指数 {10-14} → 3 指数 (104)，才是 74.94°。两者相差一档，肉眼几乎看不出，但数字完全不同。文档里原来的 {10-11} 已全部改正，并把 {10-11} 留成"反例锚点"。
2. **教材值对应的晶胞是"取整"的。** 用 a=4.99 / c=17.06 算是 74.94°（74°56′），要让 74°55′ 精确成立需要 c≈17.052。所以容差从 ±0.02° 放宽到 ±0.05°，并在文档里注明"教材值 = 取整晶胞下的标准值"。
3. **六方系的二次轴不能用 diag(1,−1,−1)。** 那会把 A·B 从 −a²/2 翻成 +a²/2，不是等距变换，群闭包直接发散（循环到 96 阶报错）。正确写法：绕 A 转 180° 是 A→A、B→−(A+B)、C→−C，必须用**基矢的像**构造矩阵，而不是抄一个对角矩阵。等轴系因为晶格本来就正交，这个错误不会暴露——所以点群操作一定要在**非正交晶胞**上验一遍群阶。

附带的第四个坑：3×3 求逆时行向量叉乘得到的是**列**；写成"行的叉乘"在等轴系碰巧也对，六方系立刻炸。

## 7. 补充验证：石英（点群 32）与原型出图

### 7.1 点群 32（三方偏形，阶 6）

- 生成元：C3（A→B、B→−(A+B)、C→C）＋ 绕 A 的二次轴（A→A、B→−(A+B)、C→−C）；闭包 6 阶。

### 7.2 三形聚形 = 18 面（教科书石英）

### 8.2 六条反馈各自的实现

1. **晶系 → 矿物 → 外形**三级选择，左栏按晶系分组。
2. **取消单形后显示该单形自己的完整外形**：生成器为每个可见子集单独求多面体，开形（如只有菱面体的"两个尖"）用 6 面方盒截断，截断面标 `clip: true`，面板上注明"开形，已用边界盒截断"。实测：只看石英柱面 = 6 个四边形柱面 + 2 个灰色截断面；柱 + r = 12 面；全显 = 18 面。
3. **统一染色**与按单形着色并列为两个模式，颜色取自矿物常见色（石英：无色 / 紫 / 黄；萤石：绿 / 紫 / 蓝；方解石：无色 / 蜜黄……），互不冲突。
4. **导出图带文字**：12 个复选框字段（矿物名、英文名、化学式、晶系、点群、单形清单、特征面角、晶胞参数、外形说明、当前可见单形、日期、署名），1×/2×/3×，深色/透明底，四个出口（保存 PNG / 复制图像 / 复制 DataURL / 新页面打开）。
5. **重置晶轴**：与"重置视角"分开——它只把 a₁/a₂/a₃/c 的显示方位复原，保留当前旋转。
6. **日本律双晶**：石英 {11-22} 双晶面，两个个体 c 轴夹角实测 **84.54°（84°33′）**，与教材一致。生成器还会为该双晶自动挑一个默认朝向（绕 c 轴 yaw），否则第二个个体常常正好指向镜头、看上去"只有一个晶体"。

### 8.3 数据置信度

- 晶胞参数（萤石 5.463；石榴石 11.53；白钨矿 a=5.243 c=11.376；绿柱石 a=9.21 c=9.19；石英 a=4.9134 c=5.4052；方解石 a=4.990 c=17.061；文石 a=4.961 b=7.967 c=5.741；石膏 a=5.68 b=15.18 c=6.29 β=118.4°；钠长石 a=8.14 b=12.79 c=7.16 α=94.3° β=116.6° γ=88.2°）标 `confidence: high`，附来源。
- 外形与 k 值是**手工调的定性外形**（`confidence: medium`），不是 BFDH 计算结果。k 的语义是"该单形的面到晶体中心的距离倍率"，只改相对大小、不改面族。

### 8.4 已知限制与踩过的坑

- **第五个坑：空多面体被当成"闭合"**。`isClosedPoly()` 对"零个面"的输入返回 `true`（没有棱，自然没有"棱被两个面共享"的反例），于是开形的截断分支永远不触发——27 个"只留一个开形"的变体渲染成空白。修法：`poly.faces.length === 0 || !isClosedPoly(poly)`。教训：**用"没有反例"定义的判据，必须先挡掉空输入**。
- 双晶用"逐个体画家算法"排序（先画远端个体，个体内按最远顶点降序），交叠处没有真实求交——视觉够用，但不严谨。
- 石膏与斜长石的"板状"必须有 {001} 封顶：只有 {010}+{110} 时沿 c 轴无界，不闭合。
- 方解石犬牙石是 {21-31} + {10-14} 聚形；单 {21-31} 是约 10:1 的长针，教学图上必须带菱面体帽子。
- 赤平投影、47 单形目录、32 点群全集仍未接（M1/M2 范围）。

## 9. 原型 v2：真并集双晶、六种光泽、导出预览

用户三条反馈（m00853）：导出必须能看见预览；要有真实晶体质感（玻璃/金刚/金属/蜡状，按矿物定）；双晶得真正融合、不能是"两个晶体戳在一起"。

### 9.1 双晶＝真并集（不再是两块体叠画）

- **做法**：`spike/make-app.mjs` 的 `buildGeometry()` 里，个体 B = `T(A)`（`T` 为双晶矩阵），然后
  `union = (∂A − B 内部) ∪ (∂B − A 内部)`。每片多边形用 `subtractConvex()`（Sutherland–Hodgman 按平面裁）切掉落在对面个体内部的部分；被裁的面重新定向（`orient(pts, n)`）保持逆时针。
- **结果**：萤石尖晶石律 16 → **52 面**，石英日本律 36 → **69 面**（两个个体各 18 面被切开后重组成公共外表面）。内部交线全部消失，只留真正的外表面——任意角度旋转都看不到内部结构。
- **代价与收尾**：并集在 T 型接点处会留下"只用一次"的边（石英日本律 6–32 条不等）和亚像素裂缝。处理办法是渲染端两点：①**只描真棱**（两面共用且法线夹角 > 5°），剖分缝一律不描；②填充时同色描边 1 px 补缝。
- **教学诚实**：接触双晶本来就该有**凹角**（日本律 84°33′ 的"肘形"接合），所以接合处的折线是真实的，不是渲染错误。两块体的相对位移（`twin.shift`，日本律取 0.78 个半高）只影响接合位置，**取向关系严格按 {11-22} 镜像**。
- **单形面数不能用并集数**：并集把一片晶面切成多块多边形，直接数会得到"六方柱 40 面"这种错值。改为用 `formPlanes(hkl, ops, L, k).length` 数该单形本身的晶面数（六方柱 6、r 6、z 6）。

### 9.2 六种光泽（按矿物给默认值）

| 光泽 | 参数（amb/diff/spec/shin/alpha） | 典型矿物 |
| --- | --- | --- |
| 不透明 | .54 / .62 / .05 / 8 / 1.00 | 受蚀变的脉石 |
| 玻璃 | .46 / .58 / .55 / 70 / 0.90 | 石英、萤石、绿柱石、文石、钠长石 |
| 金刚 | .34 / .52 / .90 / 120 / 0.96 | 石榴石、白钨矿、方解石 |
| 金属 | .30 / .55 / .78 / 36 / 1.00（高光带本体色） | 黄铁矿一类（暂未收录） |
| 蜡状 | .60 / .50 / .16 / 14 / 0.97 | 石膏 |
| 透明 | .42 / .45 / .34 / 60 / 0.46 | 光学级晶体 |

- 光照为 Blinn–Phong：`L = normalize([-0.34, 0.62, 0.72])`，`spec = pow(max(0, n·h), shin) * spec`。
- **透明不能逐片叠加**：直接给每片多边形设 `globalAlpha` 会在片与片的接缝处叠出深色描边（看起来又像"内部结构"）。改法是先把整个晶体按不透明画进离屏 canvas，再整体 `drawImage` 到主画布时设 `globalAlpha`。
- 闭合体一律**不画背面**（背面只在开形/截断时需要，否则会透出内部）。

### 9.3 导出预览

- 导出弹窗里新增 `#expPrev` 画布：**预览与保存调用同一个 `buildExportCanvas()`**，所以尺寸（900/1400/2000）、背景（深/浅/透明）、字号（小/中/大）、八个文字字段、当前旋转全部所见即所得，不会出现"预览 ≠ 导出"。

## 10. 第四轮反馈：双晶、光泽、晶纹、画幅

### 10.1 日本律双晶：从“两个晶体穿在一起”到“沿真实晶面贴合”
- 旧做法：把整块晶体过中心的平面镜像后求并集 → 两体互相穿插，结合面之外长短不等。
- 新做法（`spike/make-app.mjs` 的 `mode: "contact"`）：以**该晶面所在平面**为镜面，
  `d = max(n·v)` 取支撑距离，`B(p) = p − 2(n·p − d)n`；A 整体在 `n·x ≤ d`、B 整体在 `n·x ≥ d`，
  两体都完整、结合面之外等长。
- 石英日本律：习惯里必须带 `{11-22}`（s 面）才有平面可贴，`k = 0.99`；
  c 轴夹角 84.543°（84°33′）与教材一致；双晶变体 24 面。
- 萤石尖晶石律：两根立方体沿 `{111}` 对合（12 面）。**不能用八面体**——180° 绕 [111] 与 `{111}` 镜面都是八面体自身的对称，等于没有孪晶。

### 10.2 光泽：加掠射角反光（Fresnel）
- `shadeFace()` 增加 `fres = (1 − |n·v|)³ · M.fres`，六种光泽各给 fres 值（金刚 .58 / 玻璃 .40 / 透明 .62 / 金属 .50 / 蜡 .14 / 不透明 .06）。
- 掠射角提亮是“塑料感 vs 晶体感”的分水岭：平面着色 + 单一高光看起来像塑料，边缘泛光后才像晶体。

### 10.3 晶纹（可选）

## 11. 第五轮反馈：本地渲染升级（“第 0 步”）

用户目标：在不迁移 WebGL、不上贴图、不上游戏引擎的前提下，先把现有 2D Canvas 渲染推向玻璃/金刚/金属质感。做法是把光照模型从“凭感觉近似”换成“有物理依据的近似”。改动只在 `demo/crystal_template.html`（`LUSTERS` 表、`ENV_LIGHTS`、`shadeFace()`），`demo/crystal.html` 由 `node spike/make-app.mjs` 重新生成，未手改。

### 11.1 加了什么
- 每种光泽新增三个光学常数：`ior`（折射率）、`envI`（环境反射强度）、`metal`（金属标记）。
- `shadeFace()` 增加两项：
  - **Schlick 菲涅耳反射率**：`R0 = ((n−1)/(n+1))²`，`F = R0 + (1−R0)(1−|n·v|)^5`。石英 1.54 → 4.7%，金刚石 2.42 → 17.1%，金属 = 1。同一种“亮边”在 §10.2 里靠 `fres` 假造，现在有了物理依据，`fres` 相应降到 0.45 倍权重避免双重计分。
  - **程序化“影棚环境”反射**：`ENV_LIGHTS` 三个方向光斑 + 天地渐变，按 `r = 2(n·v)n − v` 取样。晶体转动时反射内容扫过各晶面，这正是真实晶体在固定光源下的观感。零资源文件，保持单文件 HTML 的分发优势。
- **金属光泽的关键修正**：`amb .28 / diff .54` → `.04 / .07`。金属几乎没有漫反射，颜色必须几乎全部来自环境反射；原先的漫反射项把反射淹掉了，这是第一版“六种光泽看起来一模一样”的主因。

### 11.2 三次失败的调参（都已写进代码注释）
- 柔光箱第一版 `sharp: 18`：只有反射向量落在光源 30° 以内才亮，六个光泽一个亮斑都没出现。降到 `3.5`（大面积柔光）才出现整体的“上左下亮”反射梯度。
- 高光指数沿袭了点光源 mental model（玻璃 `shin=55`、金刚 `110`）：诊断脚本逐面打印角度后发现面 13 的 `n·h = 0.94`，而 `0.94^55 ≈ 0.03`——**高光几何上存在，却被指数杀死**。降到玻璃 14 / 金刚 22 / 金属 10 / 不透明 4。教训：晶面数量少时高光瓣必须放宽，否则没有晶面能接住光。
- 诊断方法（脚本为临时文件、已删除，方法记录在此）：加载 HTML 内 `DATA`，按 QA 渲染器同一套四元数与相机，逐面打印 `n·v`、`n·h`、`r·L` 与 `shade()` 最终 RGB。**先量后调**，不要凭感觉猜参数。
- 通透度：玻璃 `alpha` .88 → .78，透明 .50 → .45。真实石英/方解石是能看穿的，原值几乎不透明。

### 11.3 仍做不到的（诚实清单）
- 色散（金刚石“火彩”）：需要波长相关折射率，平面着色做不了，留到 WebGL 版本。
- 次表面散射：只有“整块按 alpha 淡出”的近似，没有“光进入晶体再从背面透出”。
- 每像素法线扰动（岩石粗糙感）：平面着色下面内是常量，做不了。
- 金刚光泽目前读起来是“暗身体 + 亮反射”；真实钻石靠内部全反射整体发亮，这一步到不了。

### 11.4 断言
`node spike/app-check.mjs`：27 条全 PASS（六种光泽可切换、三种导出画幅文字不出界、双晶面数、18 个外形闭合）。`python spike/qa-render.py lustre` 出六联对比图 `render/qa-lustre.png`（用 36 面聚形与 24 面双晶——面太少时高光只落在一两个面上，看不出光泽差异）。

## 12. 第六轮反馈：背景 / 光照 / 通透度与光泽解耦 / 内含物

用户四点：①换背景（自然界、实验室、藏品柜等）；②光照（问要不要 WebGL）；③晶体可以有内容物，玻璃/金刚光泽下能看见；④**光泽与通透度是两件事**——光泽只代表表面对光的反射率，通透度分不透明/半透明/全透明或线性调整（金属天然不透明？），做成两个栏位 + 底下的透明度手拉滑杆。

### 12.1 对第②问的回答（结论）
**不需要 WebGL。**当前光照已经是程序化方向光（三个方向光斑 + 天地渐变环境），Canvas 2D 完全够。WebGL 才带得来的是：真实投影阴影、环境贴图（HDR）反射、色散。本机显卡（AMD 8845HS / Radeon 780M）跑本项目是填充率负载而非带宽负载，几何量只有几千三角面，2D Canvas 每帧重绘即可。

### 12.2 光泽与通透度解耦（数据结构）
- `LUSTERS` 删掉 `alpha` / `back`，只保留反射项（`amb/diff/spec/shin/fres/ior/envI/metal`）；`metallic` 加 `opaqueOnly: 1`。**光泽从此只回答“表面怎么反光”。**
- 新增独立 `TRANSP = [{opaque,1.00},{transl,0.55},{clear,0.26}]` 与 `transpById()` / `defaultTransp(m)` / `defaultAlpha(m)`。默认映射：metallic/opaque → opaque，adamantine/transparent → clear，其余 → transl。
- `mat()` 合成时：`alpha = L.opaqueOnly ? 1 : (state.alpha ?? defaultAlpha(mineral()))`。**金属光泽强制 alpha=1 并禁用滑杆**（金属天然不透明）。
- 通透度三档 + 滑杆（12–100）可线性微调，与光泽栏位完全独立。

### 12.3 五套程序化背景
`BACKGROUNDS` 五套：`dark` 深空 / `lab` 实验室（记录纸网格 + 实验台面）/ `nature` 自然界（天空 + 压低远山 + 地面）/ `cabinet` 藏品柜（暗底 + 顶部聚光 + 展台 + 暗角）/ `paper` 纸面。每项除 `draw(g,w,h)` 外还带 `amb` 与 `ambT`，作为环境光修正传进 `shadeFace()`：藏品柜 0.82 更暗、自然 1.18 更亮、纸面 1.28。**换背景不只是换底色，环境光随之变化**，晶体观感才跟着变。

### 12.4 光照
`LIGHT_V` 改为 `let` + `setLight(azDeg, elDeg)`，方位角 −180…180、高度角 −30…88。关键细节：**必须同时把 `ENV_LIGHTS[0].dir` 设成同向**，否则主光位置变了、环境反射里的柔光箱还在原处，高光与反射会错位。滑杆即时生效。

### 12.5 内含物（六种）
`INCLUSIONS` 六种，各带中文说明：金红石针（金黄针 10 根，沿 c 轴定向）/ 电气石微晶（黑八面体）/ 黄铁矿微晶（金属立方体）/ 气泡 / 多相包体（气+液+微晶）/ 愈合裂隙（薄片）。实现要点：
- 伪随机用 `mulberry32(strHash(矿物|习惯|包体))`——**同矿同习惯结果稳定**，晶体转动时包体跟着转，不会每帧跳。

## 13. 第七轮反馈：双晶根因纠正、实体桌面、内含物可见性

用户提出四条（m02229）：①五套背景除深空外都"浮在空中"，实验室该有桌子、自然界该是地面、藏品柜该有木桌、纸面也该有纸；②"把晶体放在桌子上"是否需要物理碰撞、是否负载很大、是否必须上 WebGL；③内含物基本上看不到；④萤石尖晶石律与石英日本律都明显错误，**旋转时两个体会产生奇怪的位置分离**。

### 13.1 双晶为什么会分离——三个根因（按发现顺序）

**根因一（诊断误报，教训）**：第一版诊断脚本 `spike/_tw.mjs` 读 `demo/crystal.html` 里 `DATA` 的顶点统计"落在双晶面上的顶点数"，容差写 `1e-6`。而 `DATA` 的坐标已 `toFixed(5)` 四舍五入，只有精确等于支撑距离的那一个点算命中，于是报出"萤石 1 个、石英 15 个 variant 全 1 个"的假结论。容差改 `1e-3` 后真相是：**石英只要 variant 含 s 面 `{11-22}` 就有 3–6 个顶点在双晶面上** ✔，不含 s 面的 7 个 variant 才只有 1–2 个 ✘。教训：**从已序列化的数据做几何判断，容差必须大于序列化精度**。

**根因二：接触双晶的"双晶面"不是该晶形的真实晶面**。原先用 `clipPoly(f.pts, n, 0)`——即**过晶体中心**的平面去切。若该平面不是真实晶面，两个个体只在一个顶点上相接，旋转时各自绕自己的中心转，看起来就是分离的。修复：`n = faceNormal(h3, res.L).n; d = max(n·p)` 取**支撑平面**（=晶面真正所在的平面），`B(p) = p − 2(n·p − d)n − δ·n`。这样两块都完整，A 占 `n·x∈[−e, d]`、B 占 `[d−δ, 2d+e−δ]`，**都是 d+e 长**（用户要求的"结合面之外等长"）。δ=0（双晶面是真晶面）时删掉两片重合的结合面；δ>0（只是近似的重合）时做真并集 `(∂A − B内部) ∪ (∂B − A内部)`。

**根因三：贯穿双晶不能用"镜面"建模**。萤石尖晶石律是**两个立方体沿共有 [111] 体对角线互相穿插**，不是两个八面体底面对底面（那是尖晶石本身的接触型表达）。改成 `mode:"axis", axis:[1,1,1], angle:109.471` 的 180° 旋转。因萤石属 m-3m（centrosymmetric），「{111} 镜面」与「[111] 二次轴」给出同一个双晶（σ·C₂ = 反演，反演是 m-3m 的对称操作）；又因立方体自身绕该轴有 120° 对称，等价于两个体相对转动 60°，**两个体的 <100> 棱方向夹角 arccos(−1/3) = 109°28′**（取无向线则 70°32′）。

**一个前置 bug**：`spike/make-app.mjs` 的 `twin` 输出原先只保留 `{angle, mode}`，把 `axis`/`plane`/`delta` 全丢了，导致 app 里 `habit().twin.axis` 是 `undefined`、贯穿双晶分支根本没数据可用。已改为四个字段都带。

**石英日本律参数修正**：结合面 `{11-22}={1122}` 确认，夹角 **84°33′ = 84.55°**（原先写 84.543° = 84°32′35″，不准）。按 α-石英 a=4.9134、c=5.4052 Å 反算：`(11-22)` 面与 c 轴夹角 42.26°，反射后 2×42.26 = 84.52° ≈ 84°31′ ✔。**"双晶轴 = c 轴"是错的**（那是道芬律 <0001>）。外形是 V 形（早期扇形）/板状，菱面体相交处有"假凹角"（pseudo re-entrant corner），两个体的两条 m 柱面共面平行。⚠ **"两体等大"未被任何来源证实，且有反证**（Lenart 2012 "random intergrowth of both twin individuals"；Sunagawa：双晶整体比共存单晶长得更大）——数据 note 里如实写明"此处按理想对称形展示"。

**参数结论**：石英日本律要 46 面/8 态，必须 r/z `k=0.80` + s `k=1.5`（s 面必须真的长出来，r/z 收到 k=0.80 给它让位）；k 取 0.95/0.99 时 s 面被完全切掉，只剩 12 面。另外给 `make-app.mjs` 的变体生成加 `forceMask`：接触双晶把"双晶面对应的那个单形"强制 OR 进每个 mask，否则去掉 s 面的 variant 又退化成只接一个点。

### 13.2 "放在桌面上"不需要物理、不需要 WebGL

回答 m02229 第②问：**不需要**。理由：晶体位置不是算出来的，是"读屏幕外框 + 平移/缩放"一次成型——量一遍所有顶点的投影外框 `projectedBox(project)`，若高出 `(floorY − 5%vh)/2` 就整体缩小，再令 `cy = floorY − b.ymax` 把底边贴到桌面线，最后画 6 圈同心椭圆当接触阴影。这是**一次解析求解，不是逐帧物理积分**，负载可以忽略。真实投影阴影、桌面反射才需要 WebGL（或者离屏多次绘制），当前用同心椭圆近似。第一版写成 `cy = floorY − (b.ymax−b.ymin)/2` 是"居中"不是"贴底"，晶体下半截陷进桌面里；已改为贴底，并把可用高度同步改成 `(floorY − 5%vh)/2`。

### 13.3 内含物为什么看不见——是绘制顺序，不是尺寸

`paintInclusions()` 原本被 `paintFaces()` 在**晶体之前**调用（代码注释自己写着"内含物画在晶体之前：被半透明晶面整体盖住"），于是包体先被画到背景上、再盖一层 alpha=0.55 的晶体，**自己被自己的晶体吃掉 45%**，加上尺寸本来就小、电气石色近黑，就成了"基本上看不到"。三处修复：

1. **调用点移到晶体合成之后**（`paint()` 里，晶体各层 paste 完再画包体）；
2. 可见度系数 `k = 0.30 + 0.70*(1 − M.alpha)` 并 `min(1, f.alpha*k)`：全透明→0.83、半透明→0.64、不透明→0.30；
3. 尺寸整体放大 + 颜色提亮（电气石 0.09→0.62 系、多相八面体 0.16→0.58 系）。

代价与取舍：包体现在画在晶体之上，不会"被晶面遮挡"，物理上不如真实（真实是被半透明介质衰减 + 折射放大），但对本项目的"看清包体"目标更直接。

### 13.4 实体桌面
`BACKGROUNDS` 每项加 `table: { y }`：lab 0.74（实验台，带前缘厚度、记录纸网格只画墙上段、下方压暗）/ nature 0.66（草地，远山压低到 0.54h、横向浅纹）/ cabinet 0.80（木展台，台沿 + 木纹）/ paper 0.84（纸面自身压暗）/ dark 无桌面。UI 场景面板加"放在桌面上（贴合 + 接触阴影）"勾选框，无桌面的场景自动禁用。**导出不走桌面路径**（`noTable: true`）——导出是图鉴卡不是场景图。

### 14.1 日本律"一旋转就出错"的根因：反射后绕序反向

表面症状（两个体互相穿插、随旋转剧烈变化）与第七轮"双晶面不是真实晶面"的症状高度相似，容易误判。本轮先用 `spike/_jt4.mjs` 按个体算法向统计：**修复前个体 B 有 21/23 个面法向朝内**；萤石尖晶石律（走 `subtractConvex` + `orient` 路径）0 个朝内——与"尖晶石律对了、日本律错了"完全吻合。

根因：接触双晶 `δ = 0` 分支直接 `pts: f.pts.map(T)` 做镜像，**反射是反向变换（det = −1），点的绕序跟着反**。渲染端 `n = unit(cross(pts[1]-pts[0], pts[2]-pts[0]))` 按绕序算法向，于是个体 B 每个面的法向都朝内，背面剔除把 B 的正面全部砍掉，只剩发暗的远侧面。

修复：`pts: orient(f.pts.map(T), nR(f.n))`。修复后按个体算带符号体积：日本律 0.339 / 0.338、萤石 1.080 / 1.080，均为正且两体相等。

**排除过的误判（教训，留档避免重犯）**：
- DATA 抽取正则非贪婪匹配会在嵌套对象处提前断；必须括号配匹，且 `"const DATA = ".length` 是 **13** 不是 14（写 14 会从 `"systems"` 开始匹配，depth 永远回不到 0）。
- DATA 的 `v` 是**扁平数字数组**（`V.length = 3 × 顶点数`），按"每 3 个数一个顶点"解读前会得到 `χ = 118` 这种误报；实际 mask=1111 是 F=46/E=102/V=58/χ=2 的闭合流形。
- **诊断闭合性必须按个体算带符号体积**；用"面法向与整体质心点积"对非凸双晶有假阳性（修复后仍报 2 个/个体）。

### 15.1 实现要点

- `GL_VS` 的 clip 计算与 `makeProject()` **逐字对应**（同一个 `FOC`、同一个 `max(z, 0.4)`），保证 GL 画面与 2D 棱线/晶纹/内含物投影完全重合——不然棱会飘在晶面外面。
- **正反面判定放在顶点着色器**（`vFront = step(0.0, dot(vNrm, vec3(0,0,uDist) - w))`），不在 CPU 过滤：否则晶体每转一点正反面就翻转，顶点缓冲得整个重传。缓冲内容只取决于几何与颜色。
- `GL_FS` 是 `shadeFace()` 的逐像素版，两处不同：① `v`（视线）按像素算而不是按面心算——高光在一个面上有平滑衰减，这是"塑料感 vs 晶体感"的分界，也是换 GL 最大的单项收益；② 法线是精确面法线（顶点属性整面恒定），**不平滑**（结晶学要的是平的法线 + 逐像素高光，开平滑法线会让晶体像鹅卵石）。
- `paintFaces()` 改为 dispatcher：GL 渲染 → 新建 2D layer → `lg.drawImage(glc, 0, 0, vw, vh)` → `paintOverlay()`（只画正面的同色补缝描边、晶纹、真棱）→ `g.globalAlpha = M.alpha; g.drawImage(layer, …)`。无 GL 时走 `paintFaces2D()`（迁移前的原函数整体保留为兜底）。
- 缓存戳：`gs = (GEO.stamp||0)*4 + twinShow 编码`、`cs = colorMode + twinTint + state.uniform`；`rebuildGeometry()` 给 GEO 加 `stamp` 自增。

### 15.2 过程中修掉的三个真问题

1. **`glBuild()` 原先按正反面过滤顶点** → 每转一点就要重传整个缓冲。改为不过滤、正反面在 VS 做（`GL_STRIDE` 10→9，删掉 `aAlpha`，FS 用 `uTwoSided` 决定 discard 还是压暗）。断言"旋转不重传顶点缓冲"盯住这条。
2. **`glColStamp` 漏了 `state.uniform`** → 单色模式换颜色时颜色在顶点属性里，不重传就还是旧色。
3. **`paintOverlay` 的补缝描边原先按面心着色**，与逐像素填充差几个百分点，看起来像一圈描边 → 改为逐棱按三维中点 `shadeFace(faceColor(f), wn, mv(R, mid), eye, M)` 着色。

### 16.2 第 ② 条：内含物"密度"其实是两件事混在一起

旧表用的单位是 `R0 = GEO.extent * 0.5`（晶体的外接半径），而 `polySolid(V,F,c,s)` 的顶点是 `c + V[i]*s`——八面体**跨 2s**。旧表 `size:[0.16,0.30]`、针 `len:[0.60,1.30]` 折下来包体占晶体 32%–130%，画出来像往晶体里塞了砖。

- 尺寸表全部重写：0.014–0.062 R0（针 `len` 0.30–0.95 / `thk` 0.009、气泡 0.014–0.030、愈合裂隙 0.10–0.26），数量提上来（针 14 / 电气石 6 / 黄铁矿 7 / 气泡 16 / 多相 8+3+4 / 裂隙 4）。
- `buildPart(part, rnd, R0, c, u, sz)` 新增第 6 参 `sz`，内部 `const one = (a,b) => R0 * (a + rnd()*(b-a)) * sz;`——**数量与大小彻底解耦**。
- `state.inclusion` 默认从 `null`（跟随矿物）改成 `"none"`；`state.incSize` 新参数，UI 加"大小"滑杆（25%–250%）。旧行为"换矿物自动冒出一堆包体"是反直觉的，用户明确要求默认无。

### 16.3 第 ① 条：透明度其实是三件事叠在一起

1. `paintTint()` 把整个晶体轮廓填本体色，alpha **固定 0.40** 与通透度无关 → 背景透射率被压到 `(1−0.40)×(1−alpha)` ≈ 0.44，再透明也没用。改成径向渐变 `k = 0.10 + 0.22*(1−a)`：芯 0.55k（清）、0.72 处 k、边缘 1.45k（厚），中心永远 < 0.20，挡不住背后。这是"颜色不淡掉"与"看得穿"的调和——真玻璃也是边缘厚、中心薄。
2. `paintFaces` 把 GL 填充 + 棱线整层乘 `M.alpha`，**镜面高光也一起被洗成灰雾**。真实玻璃的高光是表面反射，不随透射衰减。改成在片元着色器里逐像素给 alpha：
   `float surf = clamp(sp + refl*0.90 + fres*1.6, 0.0, 1.0); float pa = clamp(uAlpha + (1.0-uAlpha)*surf, 0.0, 1.0);`
   然后整层 `globalAlpha = 1` 一次性贴回——整层再乘一次会把刚做对的又洗掉。
3. **最关键**：背景内容物（标尺、试管、标签、草丛、木块）全都画在 `w*0.5 ± u*0.16…0.42`，即晶体**旁边**而不是身后。晶体正后方空无一物，"透过去看不见内容"是必然的。新增 `drawSceneProps(g, id, w, h)`：每场景在晶体正后方画横标尺 + 竖杆 + 4 枚色块（五套配色 `SCENE_PROPS`），`paint()` 与 `buildExportCanvas()` 两处都调，导出与所见一致。

顺带把滑杆语义掰正：`#alphaR` 原来 min=12、往右越发实，与"透明度 95%"的直觉相反。现在读数就是**透明度百分比**（`transparency = round((1-alpha)*100)`），`state.alpha = 1 - value/100`。

### 16.4 第 ③ 条：道芬律与巴西律根本不该画成两个晶体

查证结论：两者都是**转变双晶 / 反射双晶**——道芬律是绕 c 轴 [0001] 转 180°，α↔β 转变（573 °C）时相邻两域选了不同旋向、冷却后被冻结；巴西律是 {11-20} 镜面反射，左右旋石英互生。**两个体的外部晶形完全同名同向、c 轴严格平行，肉眼与普通放大镜都看不出来**，只能靠刻蚀或正交偏光看畴。

所以旧版"两个等长棱柱叠在一起"从根上就是错的。改成新的 `mode: "domain"` 分支：不复制个体、不做并集，只算一个域界截面（`sectionFromPolys`），渲染端 `drawTwinDomain()` 画淡填充 + 虚线。UI 给一个"显示域界"开关并写明"关掉就是肉眼所见"——**能关掉这件事本身才是知识点**。

同时把两者的六方柱 `k` 从 0.95 降到 0.60：否则 r/z 会把柱面完全吃掉，只剩六方双锥，"柱状"都看不出来。

### 16.5 第 ④ 条：日本律切掉下方晶头（`cutWithCap`）

自然界日本律几乎总是长在基质上，下方的晶头不发育。新增 `cutWithCap(polys, n, d)`：用半空间切掉底部并补上断面。截断面取双晶整体"下方"＝两体 c 轴平分线的反向，**单一平面**（按每个体自己的 c 轴分别切会把连接处切掉，两块彻底分开——试过，错）。`cutBottom` 试 0.12（切口几乎看不出）与 **0.20（最终值，切口明显且仍连成一体）**。

`cutWithCap` 踩了两个坑，都是"补面要跟切口严格缝合"：

1. **只用凸包补面 → 网格破洞**。双晶并集是凹的（肘形），凸包会盖过头，留下 12 条"只用一次的棱"、χ=0。改成统计无向边使用次数，取恰好用一次且两端都在切平面上的边，串成环再补面。
2. **补面发成一块扇形多边形 → 仍留 2 条 once-edge**。`[c, p0, p1, …, pk]` 的两条辐条边 `c→p0`、`pk→c` 在别处没有配对。改成发成**三角形** `[c, p_i, p_{i+1}]`，辐条边成对共享 → 全部闭合。

修完 8 个变体全部 χ=2、0 条只用一次的棱（mask 1111 是 56 顶点 / 108 棱 / 54 面）。

### 16.6 顺带修的：贯穿双晶"只看个体"是碎三角

萤石尖晶石律是贯穿双晶，并集把"被对方包住"的那几片面删掉了——单独看一个个体就是个**开壳**，拆解后满天碎三角。修法：并集之外再带一份"完整个体"几何（`hid: 1` 标记），合在一起时不画，只有拆开或只看单个个体时才切换过去。修完萤石的拆解是两个干净的完整立方体。

### 17.2 棱线脱离的根因：`gl_Position.w` 写成了 `z`

这是本轮最实的一个 bug，而且它**从 WebGL 首版提交 `48425fe` 起就存在**（用 `git log -L 1240,1250` 确认），之前几轮"修好了"只是没触发到最明显的视角。

```glsl
gl_Position = vec4(
  ((uCx + w.x * uFoc / z) / uVw) * 2.0 - 1.0,
  1.0 - ((uCy - w.y * uFoc / z) / uVh) * 2.0,
  (2.0 * (z - uZn) / max(uZf - uZn, 1e-4)) - 1.0,
  z);        // ← 致命：GPU 会把 clip.xyz 全部除以 clip.w
```

GPU 在裁剪/NDC 阶段做的是 `ndc = clip.xyz / clip.w`。xy 已经是换算好的 NDC，w 却给了 `z`（≈5.6–8.4），于是**画面整体再缩 1/z 并往中心吸**；2D 棱线不除，于是棱线整片飘在晶体外。而每个顶点的 z 随旋转变化 → 呼吸式漂移，"一转就错"。

改成 `1.0`（深度走 `gl_FragDepth`/深度缓冲，与 w 无关）。

**为什么断言没抓住**：原有的"clip 公式同源"断言是**照着重写一遍公式再比**——它证明"我重写的和我重写的一样"，证明不了 GPU 真正看到的 clip 空间。新增断言直接抠 `GL_VS` 源码里 `gl_Position = vec4(...)` 的四个分量，要求第 4 个是常量 `1.0`。

### 18.2 根因：配色缓存戳按"颜色字符串长度"算

`glRender()` 的配色戳原来是 `+ String(state.uniform).length * 8`——**所有 hex 都是 7 个字符，同长换色戳不变，顶点缓冲不重传**。棱线走 CPU 的 `paintOverlay`（现算 `faceColor`）所以换了色，GL 填充还是旧色，于是"只有棱线变色、整体不变"；紫水晶"只剩棱线发紫、整体近乎透明"也是同一个根因（缓冲里是按单形配色的蓝/粉/绿，而新配色是紫）。

改为内容哈希：

```js
const strHash = (s) => { let h = 2166136261; for (let i = 0; i < s.length; i++) { h = Math.imul(h ^ s.charCodeAt(i), 16777619); } return (h >>> 0) % 1000003; };
const cs = (state.colorMode === "mineral" ? 2 : 1) + (state.twinTint ? 1 : 0) + (state.uniform ? 4 : 0) + strHash(String(state.uniform || ""));
```

教训：**缓存戳必须由内容决定，不能由内容的某个统计量决定**（长度是个烂统计量——hex 全都一样长）。

## §19 第十三轮：透明度的语义、光泽顺序与联动、金刚色散

用户五条（m06655）：①透明度稍高就能看穿、颜色掉得太快、"全透明"只到 74%；②点金属后通透度不能立刻禁用；③光泽应按反射率排成 蜡状 < 玻璃 < 金刚 < 金属；④金刚光泽黑漆漆、没有火彩；⑤上了 WebGL 亮度应该更强。

### 19.1 "全透明只有 74%"——通透度档位本身就错了

`TRANSP` 里 `clear` 一直写的是 `alpha: 0.26`，所以滑杆读数 `(1-0.26)*100 = 74%`。这不是显示 bug，是档位定义错了：全透明就该是 0。

| 档位 | 旧 alpha | 新 alpha | 读数 |
|---|---|---|---|
| 不透明 | 1.00 | 1.00 | 0% |
| 半透明 | 0.55 | 0.62 | 38% |
| 全透明 | 0.26 | **0.00** | **100%** |

但 alpha=0 会带来新问题：晶面彻底消失，只剩一圈棱线。所以片元着色器里加了"面底线"：

```glsl
float floorA = 0.20 + 0.26 * clamp(uDiff * lam + sp, 0.0, 1.0);
float pa = clamp(max(uAlpha, floorA) + (1.0 - uAlpha) * surf, 0.0, 1.0);
```

**全透明时晶面仍按各自明暗留 20%–46% 的不透明度**，于是"能看穿、但看得出棱角"。物理上也对：真正透明的水晶就是只剩棱、高光和背景畸变。

### 19.2 "颜色掉得太快"——补一层「有色透射」

透明度一高颜色就没了，是因为过去只有"往下盖"的一条路（晶面 alpha 越低，本体色越淡）。真实的彩色玻璃不是这样：**透过去的背景被染了色**。

`paintFaces()` 末尾加了乘算层：

```js
const tr = 1 - M.alpha;
if (tr > 0.01) {
  g.clip();  g.globalAlpha = tr * 0.90;
  g.globalCompositeOperation = "multiply";
  g.fillStyle = rgbStr(bc);  // 越透明越接近无色
  g.fillRect(0, 0, vw, vh);
}
```

不透明时 `tr=0` 完全不起作用；全透明时相当于一块彩色滤色片 —— 背景还在，只是染上了晶体的颜色。**颜色不会消失，只会变成"透过来的那层彩色"。**

同一次改动里，本体色层 `paintTint` 的厚度改成三角形分布 `k = 0.30 * (1 - |2a-1|)`：不透明时靠晶面、全透明时靠有色透射，中间（半透明）才需要这层平涂。

### 19.3 点金属后通透度不立刻禁用

`renderLusters()` 的按钮只调了 `draw()`，没有调 `renderTransp()`：

```js
b.onclick = () => { state.luster = id; renderLusters(); renderTransp(); draw(); };
```

`disabled` 状态写在 `renderTransp()` 里，所以过去要等下一次 `syncPanels()`（比如换颜色）才更新。加上 `renderTransp()` 后立即生效。

| 玻璃 | .40 | .55 | .75 | 14 | 1.54 | .52 | .07 |
| 金刚 | .13 | .22 | 1.25 | 30 | 2.42 | 1.15 | .55 |

### 19.5 金刚的"火彩"：便宜版色散

真实色散要红绿蓝各算一条折射路径。这里用反射方向的相位生成一条循环谱色，只乘在高光与环境反射上（漫反射不带色散）：

```glsl
float phase = dot(rdir, vec3(0.5773)) * 1.7 + dot(n, v) * 0.6;
vec3 fire = 0.5 + 0.5 * cos(6.28318 * (vec3(0.0, 0.33, 0.67) + phase));
vec3 specCol = mix(vec3(1.0), fire, clamp(uDisp, 0.0, 1.0));
```

`uDisp` 由光泽给（金刚 .55、金属 .10、玻璃 .07、蜡状 0）。**这不是真火彩**（没有分光，也没有随观察角变化的彩虹边），只是让高光带上色偏。

### 19.6 亮度：统一曝光补偿

三灯归一化之后整体偏暗。加 `EXPO = 1.10`（JS）、`uExpo`（GLSL）、`EXPO`（Python 复刻层），在最后乘一次，三处必须同值。金刚光泽的 `amb/diff` 也从上一轮的 .09/.18 提回 .13/.22（那时为了"暗身体+亮高光"压得太狠，用户反馈"黑漆漆"）。

### 19.7 Python 复刻层修了一个真 bug

`Image.paste(im, box, mask)` **只用 mask 当 alpha，会忽略 `im` 自己的 alpha 通道**。旧代码 `lay = (色, 102)` + `paste(..., mask)` 于是把本体色按 255 全不透明糊上去——半透明晶体的晶面被整块盖住，QA 图里钻石变成一块死黄。必须把两个 alpha 相乘（`ImageChops.multiply(mask, amask)`）。这个 bug 让前几轮的透明度 QA 图全部失真。

### 19.9 关掉棱线后晶体的棱仍然"异常突出"

用户 m06941：不显示棱线时，棱还是特别明显，自然晶体不该这样。

根因不是"棱线开关没生效"，而是 `paintOverlay()` 里有一条**逐棱补缝描边**：

```js
// 旧代码（已删）
g.lineWidth = 1;
for (每条棱) {
  g.strokeStyle = rgbStr(shadeFace(faceColor(f), wn, mv(R, mid), eye, M)); // 棱中点一次着色
  g.stroke();
}
```

它的本意是盖住 GL 抗锯齿在相邻面之间留下的亚像素裂缝（不盖就会透出背景，成为一圈黑线）。但它取色用的是**棱中点的一次着色**，而 GL 是**逐像素着色**：掠射角处菲涅耳变化极快，两者对不上 → 每条棱成了一道与填充不同的细线；棱线开关关掉的只是后面那条深色描边，这条还在。所以"关掉棱线仍然看得见棱"。

正确做法是从源头消掉裂缝，而不是事后描边：顶点着色器里加面心属性 `aCen`，把每个面沿"面心 → 顶点"方向外扩约 1 px，让相邻面互相压住：

```glsl
vec2 sp = screen(w), sc = screen(uRot * aCen);
vec2 d = sp - sc; float dl = length(d);
if (dl > 1e-5) sp += d / dl * vec2(2.0 / uVw, 2.0 / uVh) * 1.0;
```

同时删掉补缝描边、`GL_STRIDE` 9 → 12（pos3+nrm3+col3+cen3）、`glAttr` 补 `aCen`。这样关掉棱线后，面与面之间只剩**真实着色差**，不会再有假线。

新增两条断言：顶点着色器必须带 `layout(location=3) in vec3 aCen` 与外扩算式且 `GL_STRIDE === 12`；`paintOverlay` 的源码里不许再出现 `shadeFace(`（防止补缝描边被改回来）。断言 159 → **161 条全 PASS**。

**③ 火彩挪到内部，表面保持白色高光。** 这是用户点出的真问题。原实现用一条循环谱色乘在**表面高光与环境反射**上，等于给抛光面刷了彩虹。真实情况正相反：

```glsl
vec3 fireIn = vec3(envSample(refract(-v, n, 1.0/(uIor*0.975))).r,
                   envSample(refract(-v, n, 1.0/uIor)).g,
                   envSample(refract(-v, n, 1.0/(uIor*1.025))).b);
vec3 internal = fireIn * fireAmt * (1.0 - F) * 0.85;
```

`fireAmt` 随透射率上升、随掠射角增强——所以火彩只在**晶体内部靠近边缘**的地方闪，表面那层始终是干净的白高光。

### 19.15 为什么"六盏灯看不出区别"——归一化的分母错了

用户 m07340 ①。加灯没效果不是灯不够亮，而是**归一化把副光稀释掉了**：

```js
lam = Math.pow(lam / LIGHT_SUM, 1.25);   // LIGHT_SUM = 所有灯强度之和
```

灯越多，分母越大，主光的相对份额反而越小。纸面场景主光 1.06、总和 3.48 → 主光只占 **30%**；上一版三盏灯时是 1.00/1.94 ≈ **52%**。也就是说**加灯让画面更平了**，和用户"完全没区别"的观察完全一致。

改成只按主光归一，副光变成纯加法：

```glsl
float keyI = max(uLigInt[0].x, 0.05);
lam = pow(lam / keyI, 1.12) * uKeyExpo;   // uKeyExpo = 0.62
```

亮面仍归一化到 1 附近（乘 0.62 是为了给副光留出加法余量），暗面则由副光抬起来——这正是多灯该有的效果：**明暗关系不变，暗部有内容**。高光同理，分母改用主光的 `inten*spec`，否则六盏灯把高光也平摊没了。

`fluorite.colors` 补 `{ zh: "红色", en: "Red", hex: "#c2544f" }`。萤石的红色来自晶格中的色心（电子被辐照激发后被缺陷俘获），和绿色、紫色是同一类成因。

### 19.14 方解石：复三方双锥 + 双晶

- 新外形 `ditrigonal`「复三方双锥」：单形 `{11-23}` 在 -3m 里给 **12 个三角面**（上下各 6 面、彼此错开 60°），配 `{10-10}` 六方柱与 `{0001}` 底轴面把它截成矮胖的桶状（不截的话 c 轴 17 Å 会让它长成一根针）。
- 新外形 `shuriken-twin`「两个复三方双锥沿 {10-10} 横向接合」：接触双晶，两个个体等大、沿柱面镜像，正面看四个尖端张开。

**诚实说明**：方解石最著名的双晶是 `{01-12}` 的「蝴蝶双晶」和 `{0001}` 的「底轴面双晶」，并不是这一个。「忍者镖」这个形态是我按描述反推的建模，双晶面取 `{10-10}` 也是推断——**如果和你看到的图不一样，把图发我，我按真实双晶律改**（现有引擎支持接触型与贯穿型两种）。
