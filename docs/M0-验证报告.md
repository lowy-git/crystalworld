## 2. 数据流（与规格文档 §C 一致）

```
晶胞 (a,b,c,α,β,γ) → 直基 A,B,C → 倒易基 A*,B*,C*
(hkl) → n = hA*+kB*+lC* → 单位法线 n̂，面距 d = 1/|n|
点群 3×3 正交矩阵 → 把 n̂ 铺成面族 {n̂ᵢ}
多面体 = ∩ {x : n̂ᵢ·x ≤ kᵢ·d}   ← 三元面交点 + 可行性筛选 + 按面归并顶点环 + 棱去重
校验：欧拉 V − E + F = 2
```

## 4. 踩到的三个坑（都已写进代码注释）

1. **教材 74°55′ 的指数是 {10-14}，不是 {10-11}。** 4 指数 {10-11} → 3 指数 (101)，算出 65.82°；4 指数 {10-14} → 3 指数 (104)，才是 74.94°。两者相差一档，肉眼几乎看不出，但数字完全不同。文档里原来的 {10-11} 已全部改正，并把 {10-11} 留成"反例锚点"。
2. **教材值对应的晶胞是"取整"的。** 用 a=4.99 / c=17.06 算是 74.94°（74°56′），要让 74°55′ 精确成立需要 c≈17.052。所以容差从 ±0.02° 放宽到 ±0.05°，并在文档里注明"教材值 = 取整晶胞下的标准值"。
3. **六方系的二次轴不能用 diag(1,−1,−1)。** 那会把 A·B 从 −a²/2 翻成 +a²/2，不是等距变换，群闭包直接发散（循环到 96 阶报错）。正确写法：绕 A 转 180° 是 A→A、B→−(A+B)、C→−C，必须用**基矢的像**构造矩阵，而不是抄一个对角矩阵。等轴系因为晶格本来就正交，这个错误不会暴露——所以点群操作一定要在**非正交晶胞**上验一遍群阶。

附带的第四个坑：3×3 求逆时行向量叉乘得到的是**列**；写成"行的叉乘"在等轴系碰巧也对，六方系立刻炸。

## 7. 补充验证：石英（点群 32）与原型出图

用户提出"加一个石英"之后补做的一轮，验证内核在**极性点群**（无对称中心、无镜面）上的行为。

### 7.1 点群 32（三方偏形，阶 6）

- 生成元：C3（A→B、B→−(A+B)、C→C）＋ 绕 A 的二次轴（A→A、B→−(A+B)、C→−C）；闭包 6 阶。

### 7.2 三形聚形 = 18 面（教科书石英）

| 项 | 实测 |

### 8.2 六条反馈各自的实现

1. **晶系 → 矿物 → 外形**三级选择，左栏按晶系分组。
2. **取消单形后显示该单形自己的完整外形**：生成器为每个可见子集单独求多面体，开形（如只有菱面体的"两个尖"）用 6 面方盒截断，截断面标 `clip: true`，面板上注明"开形，已用边界盒截断"。实测：只看石英柱面 = 6 个四边形柱面 + 2 个灰色截断面；柱 + r = 12 面；全显 = 18 面。
3. **统一染色**与按单形着色并列为两个模式，颜色取自矿物常见色（石英：无色 / 紫 / 黄；萤石：绿 / 紫 / 蓝；方解石：无色 / 蜜黄……），互不冲突。
4. **导出图带文字**：12 个复选框字段（矿物名、英文名、化学式、晶系、点群、单形清单、特征面角、晶胞参数、外形说明、当前可见单形、日期、署名），1×/2×/3×，深色/透明底，四个出口（保存 PNG / 复制图像 / 复制 DataURL / 新页面打开）。
5. **重置晶轴**：与"重置视角"分开——它只把 a₁/a₂/a₃/c 的显示方位复原，保留当前旋转。
6. **日本律双晶**：石英 {11-22} 双晶面，两个个体 c 轴夹角实测 **84.54°（84°33′）**，与教材一致。生成器还会为该双晶自动挑一个默认朝向（绕 c 轴 yaw），否则第二个个体常常正好指向镜头、看上去"只有一个晶体"。

### 8.3 数据置信度

- 晶胞参数（萤石 5.463；石榴石 11.53；白钨矿 a=5.243 c=11.376；绿柱石 a=9.21 c=9.19；石英 a=4.9134 c=5.4052；方解石 a=4.990 c=17.061；文石 a=4.961 b=7.967 c=5.741；石膏 a=5.68 b=15.18 c=6.29 β=118.4°；钠长石 a=8.14 b=12.79 c=7.16 α=94.3° β=116.6° γ=88.2°）标 `confidence: high`，附来源。
- 外形与 k 值是**手工调的定性外形**（`confidence: medium`），不是 BFDH 计算结果。k 的语义是"该单形的面到晶体中心的距离倍率"，只改相对大小、不改面族。

### 8.4 已知限制与踩过的坑

- **第五个坑：空多面体被当成"闭合"**。`isClosedPoly()` 对"零个面"的输入返回 `true`（没有棱，自然没有"棱被两个面共享"的反例），于是开形的截断分支永远不触发——27 个"只留一个开形"的变体渲染成空白。修法：`poly.faces.length === 0 || !isClosedPoly(poly)`。教训：**用"没有反例"定义的判据，必须先挡掉空输入**。
- 双晶用"逐个体画家算法"排序（先画远端个体，个体内按最远顶点降序），交叠处没有真实求交——视觉够用，但不严谨。
- 石膏与斜长石的"板状"必须有 {001} 封顶：只有 {010}+{110} 时沿 c 轴无界，不闭合。
- 方解石犬牙石是 {21-31} + {10-14} 聚形；单 {21-31} 是约 10:1 的长针，教学图上必须带菱面体帽子。
- 赤平投影、47 单形目录、32 点群全集仍未接（M1/M2 范围）。

## 9. 原型 v2：真并集双晶、六种光泽、导出预览

用户三条反馈（m00853）：导出必须能看见预览；要有真实晶体质感（玻璃/金刚/金属/蜡状，按矿物定）；双晶得真正融合、不能是"两个晶体戳在一起"。

### 9.1 双晶＝真并集（不再是两块体叠画）

- **做法**：`spike/make-app.mjs` 的 `buildGeometry()` 里，个体 B = `T(A)`（`T` 为双晶矩阵），然后
  `union = (∂A − B 内部) ∪ (∂B − A 内部)`。每片多边形用 `subtractConvex()`（Sutherland–Hodgman 按平面裁）切掉落在对面个体内部的部分；被裁的面重新定向（`orient(pts, n)`）保持逆时针。
- **结果**：萤石尖晶石律 16 → **52 面**，石英日本律 36 → **69 面**（两个个体各 18 面被切开后重组成公共外表面）。内部交线全部消失，只留真正的外表面——任意角度旋转都看不到内部结构。
- **代价与收尾**：并集在 T 型接点处会留下"只用一次"的边（石英日本律 6–32 条不等）和亚像素裂缝。处理办法是渲染端两点：①**只描真棱**（两面共用且法线夹角 > 5°），剖分缝一律不描；②填充时同色描边 1 px 补缝。
- **教学诚实**：接触双晶本来就该有**凹角**（日本律 84°33′ 的"肘形"接合），所以接合处的折线是真实的，不是渲染错误。两块体的相对位移（`twin.shift`，日本律取 0.78 个半高）只影响接合位置，**取向关系严格按 {11-22} 镜像**。
- **单形面数不能用并集数**：并集把一片晶面切成多块多边形，直接数会得到"六方柱 40 面"这种错值。改为用 `formPlanes(hkl, ops, L, k).length` 数该单形本身的晶面数（六方柱 6、r 6、z 6）。

### 9.2 六种光泽（按矿物给默认值）

| 光泽 | 参数（amb/diff/spec/shin/alpha） | 典型矿物 |
| --- | --- | --- |
| 不透明 | .54 / .62 / .05 / 8 / 1.00 | 受蚀变的脉石 |
| 玻璃 | .46 / .58 / .55 / 70 / 0.90 | 石英、萤石、绿柱石、文石、钠长石 |
| 金刚 | .34 / .52 / .90 / 120 / 0.96 | 石榴石、白钨矿、方解石 |
| 金属 | .30 / .55 / .78 / 36 / 1.00（高光带本体色） | 黄铁矿一类（暂未收录） |
| 蜡状 | .60 / .50 / .16 / 14 / 0.97 | 石膏 |
| 透明 | .42 / .45 / .34 / 60 / 0.46 | 光学级晶体 |

- 光照为 Blinn–Phong：`L = normalize([-0.34, 0.62, 0.72])`，`spec = pow(max(0, n·h), shin) * spec`。
- **透明不能逐片叠加**：直接给每片多边形设 `globalAlpha` 会在片与片的接缝处叠出深色描边（看起来又像"内部结构"）。改法是先把整个晶体按不透明画进离屏 canvas，再整体 `drawImage` 到主画布时设 `globalAlpha`。
- 闭合体一律**不画背面**（背面只在开形/截断时需要，否则会透出内部）。

### 9.3 导出预览

- 导出弹窗里新增 `#expPrev` 画布：**预览与保存调用同一个 `buildExportCanvas()`**，所以尺寸（900/1400/2000）、背景（深/浅/透明）、字号（小/中/大）、八个文字字段、当前旋转全部所见即所得，不会出现"预览 ≠ 导出"。

## 10. 第四轮反馈：双晶、光泽、晶纹、画幅

### 10.1 日本律双晶：从“两个晶体穿在一起”到“沿真实晶面贴合”
- 旧做法：把整块晶体过中心的平面镜像后求并集 → 两体互相穿插，结合面之外长短不等。
- 新做法（`spike/make-app.mjs` 的 `mode: "contact"`）：以**该晶面所在平面**为镜面，
  `d = max(n·v)` 取支撑距离，`B(p) = p − 2(n·p − d)n`；A 整体在 `n·x ≤ d`、B 整体在 `n·x ≥ d`，
  两体都完整、结合面之外等长。
- 石英日本律：习惯里必须带 `{11-22}`（s 面）才有平面可贴，`k = 0.99`；
  c 轴夹角 84.543°（84°33′）与教材一致；双晶变体 24 面。
- 萤石尖晶石律：两根立方体沿 `{111}` 对合（12 面）。**不能用八面体**——180° 绕 [111] 与 `{111}` 镜面都是八面体自身的对称，等于没有孪晶。

### 10.2 光泽：加掠射角反光（Fresnel）
- `shadeFace()` 增加 `fres = (1 − |n·v|)³ · M.fres`，六种光泽各给 fres 值（金刚 .58 / 玻璃 .40 / 透明 .62 / 金属 .50 / 蜡 .14 / 不透明 .06）。
- 掠射角提亮是“塑料感 vs 晶体感”的分水岭：平面着色 + 单一高光看起来像塑料，边缘泛光后才像晶体。

### 10.3 晶纹（可选）
- 只在石英柱面、萤石立方面上画：`STRIATION = { quartz: {form:0, axis:"c", step:4}, fluorite: {form:0, axis:"diag", step:5} }`。
- 方向由晶轴推出、随晶体一起旋转：`d = normalize(cross(axis, n))`，裁剪到面内，一明一暗两遍叠出细纹。
- 面板有「晶纹」开关（默认开）。

### 10.4 导出画幅
- 三档：4:3（1400×1050）、9:16（1080×1920）、16:9（1920×1080）。
- 横版（16:9）走左右分栏：晶体占左侧，文字右侧纵列，中间竖分隔线；竖版与常规仍为上下布局。

## 11. 第五轮反馈：本地渲染升级（“第 0 步”）

用户目标：在不迁移 WebGL、不上贴图、不上游戏引擎的前提下，先把现有 2D Canvas 渲染推向玻璃/金刚/金属质感。做法是把光照模型从“凭感觉近似”换成“有物理依据的近似”。改动只在 `demo/crystal_template.html`（`LUSTERS` 表、`ENV_LIGHTS`、`shadeFace()`），`demo/crystal.html` 由 `node spike/make-app.mjs` 重新生成，未手改。

### 11.1 加了什么
- 每种光泽新增三个光学常数：`ior`（折射率）、`envI`（环境反射强度）、`metal`（金属标记）。
- `shadeFace()` 增加两项：
  - **Schlick 菲涅耳反射率**：`R0 = ((n−1)/(n+1))²`，`F = R0 + (1−R0)(1−|n·v|)^5`。石英 1.54 → 4.7%，金刚石 2.42 → 17.1%，金属 = 1。同一种“亮边”在 §10.2 里靠 `fres` 假造，现在有了物理依据，`fres` 相应降到 0.45 倍权重避免双重计分。
  - **程序化“影棚环境”反射**：`ENV_LIGHTS` 三个方向光斑 + 天地渐变，按 `r = 2(n·v)n − v` 取样。晶体转动时反射内容扫过各晶面，这正是真实晶体在固定光源下的观感。零资源文件，保持单文件 HTML 的分发优势。
- **金属光泽的关键修正**：`amb .28 / diff .54` → `.04 / .07`。金属几乎没有漫反射，颜色必须几乎全部来自环境反射；原先的漫反射项把反射淹掉了，这是第一版“六种光泽看起来一模一样”的主因。

### 11.2 三次失败的调参（都已写进代码注释）
- 柔光箱第一版 `sharp: 18`：只有反射向量落在光源 30° 以内才亮，六个光泽一个亮斑都没出现。降到 `3.5`（大面积柔光）才出现整体的“上左下亮”反射梯度。
- 高光指数沿袭了点光源 mental model（玻璃 `shin=55`、金刚 `110`）：诊断脚本逐面打印角度后发现面 13 的 `n·h = 0.94`，而 `0.94^55 ≈ 0.03`——**高光几何上存在，却被指数杀死**。降到玻璃 14 / 金刚 22 / 金属 10 / 不透明 4。教训：晶面数量少时高光瓣必须放宽，否则没有晶面能接住光。
- 诊断方法（脚本为临时文件、已删除，方法记录在此）：加载 HTML 内 `DATA`，按 QA 渲染器同一套四元数与相机，逐面打印 `n·v`、`n·h`、`r·L` 与 `shade()` 最终 RGB。**先量后调**，不要凭感觉猜参数。
- 通透度：玻璃 `alpha` .88 → .78，透明 .50 → .45。真实石英/方解石是能看穿的，原值几乎不透明。

### 11.3 仍做不到的（诚实清单）
- 色散（金刚石“火彩”）：需要波长相关折射率，平面着色做不了，留到 WebGL 版本。
- 次表面散射：只有“整块按 alpha 淡出”的近似，没有“光进入晶体再从背面透出”。
- 每像素法线扰动（岩石粗糙感）：平面着色下面内是常量，做不了。
- 金刚光泽目前读起来是“暗身体 + 亮反射”；真实钻石靠内部全反射整体发亮，这一步到不了。

### 11.4 断言
`node spike/app-check.mjs`：27 条全 PASS（六种光泽可切换、三种导出画幅文字不出界、双晶面数、18 个外形闭合）。`python spike/qa-render.py lustre` 出六联对比图 `render/qa-lustre.png`（用 36 面聚形与 24 面双晶——面太少时高光只落在一两个面上，看不出光泽差异）。

## 12. 第六轮反馈：背景 / 光照 / 通透度与光泽解耦 / 内含物

用户四点：①换背景（自然界、实验室、藏品柜等）；②光照（问要不要 WebGL）；③晶体可以有内容物，玻璃/金刚光泽下能看见；④**光泽与通透度是两件事**——光泽只代表表面对光的反射率，通透度分不透明/半透明/全透明或线性调整（金属天然不透明？），做成两个栏位 + 底下的透明度手拉滑杆。

### 12.1 对第②问的回答（结论）
**不需要 WebGL。**当前光照已经是程序化方向光（三个方向光斑 + 天地渐变环境），Canvas 2D 完全够。WebGL 才带得来的是：真实投影阴影、环境贴图（HDR）反射、色散。本机显卡（AMD 8845HS / Radeon 780M）跑本项目是填充率负载而非带宽负载，几何量只有几千三角面，2D Canvas 每帧重绘即可。

### 12.2 光泽与通透度解耦（数据结构）
- `LUSTERS` 删掉 `alpha` / `back`，只保留反射项（`amb/diff/spec/shin/fres/ior/envI/metal`）；`metallic` 加 `opaqueOnly: 1`。**光泽从此只回答“表面怎么反光”。**
- 新增独立 `TRANSP = [{opaque,1.00},{transl,0.55},{clear,0.26}]` 与 `transpById()` / `defaultTransp(m)` / `defaultAlpha(m)`。默认映射：metallic/opaque → opaque，adamantine/transparent → clear，其余 → transl。
- `mat()` 合成时：`alpha = L.opaqueOnly ? 1 : (state.alpha ?? defaultAlpha(mineral()))`。**金属光泽强制 alpha=1 并禁用滑杆**（金属天然不透明）。
- 通透度三档 + 滑杆（12–100）可线性微调，与光泽栏位完全独立。

### 12.3 五套程序化背景
`BACKGROUNDS` 五套：`dark` 深空 / `lab` 实验室（记录纸网格 + 实验台面）/ `nature` 自然界（天空 + 压低远山 + 地面）/ `cabinet` 藏品柜（暗底 + 顶部聚光 + 展台 + 暗角）/ `paper` 纸面。每项除 `draw(g,w,h)` 外还带 `amb` 与 `ambT`，作为环境光修正传进 `shadeFace()`：藏品柜 0.82 更暗、自然 1.18 更亮、纸面 1.28。**换背景不只是换底色，环境光随之变化**，晶体观感才跟着变。

### 12.4 光照
`LIGHT_V` 改为 `let` + `setLight(azDeg, elDeg)`，方位角 −180…180、高度角 −30…88。关键细节：**必须同时把 `ENV_LIGHTS[0].dir` 设成同向**，否则主光位置变了、环境反射里的柔光箱还在原处，高光与反射会错位。滑杆即时生效。

### 12.5 内含物（六种）
`INCLUSIONS` 六种，各带中文说明：金红石针（金黄针 10 根，沿 c 轴定向）/ 电气石微晶（黑八面体）/ 黄铁矿微晶（金属立方体）/ 气泡 / 多相包体（气+液+微晶）/ 愈合裂隙（薄片）。实现要点：
- 伪随机用 `mulberry32(strHash(矿物|习惯|包体))`——**同矿同习惯结果稳定**，晶体转动时包体跟着转，不会每帧跳。
- 位置在 `R0×0.04–0.20` 球内，`u` 在 `orient:"c"` 时与 c 轴插值 0.55（金红石针基本沿 c 轴，符合真实石英）。
- **每个包体的全部顶点必须 `inside(p)` 才收下**（试 16 次 + 1/.82/.66/.52/.4 逐级缩小），保证没有任何包体探出晶面。
- 绘制在晶体之前（painter），被半透明晶面整体盖住：**通透度越低越看得清，不透明时自动不可见**——与真实观察一致。
- 密度滑杆 0–100（0 = 清空）。

### 12.6 QA 复刻层同步（`spike/qa-render.py`）
新增 `set_light()`、新 `LUSTERS`、`TRANSP`/`default_transp`、`BACKGROUNDS`/`draw_bg()`、`INCL_MAT`/`INCL_SHAPES`/`INCLUSIONS`/`build_inclusions`/`_build_part`/`_solid_faces`/`_ring`/`_perp`，并新增四个 CLI 模式：`scene`（五背景）/ `incl`（六包体）/ `transp`（alpha 阶梯）/ `light`（四组光照角度）。

**一个值得记住的坑**：Python 版最初把包体画进晶体所在的同一层，再整层乘 alpha——结果包体被自己的晶体层完全盖住，肉眼与数值都显示“零差异”。改为**包体画到背景层、晶体画透明层再按 alpha 盖上**才正确（与 JS 逐面 `globalAlpha` 等效）。教训：半透明合成必须复刻真实的绘制顺序，不能只复刻最终 alpha。
