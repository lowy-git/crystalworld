# 产地晶习 / 矿物志 · 规划 v0.1（第二十一轮，待用户确认后实施）

> 用户设想：每种矿物按产地开专属页面——不同产地有不同晶习/聚生习惯（不只单晶与简单双晶，
> 更多是特征性的连生、共生、集合体）。例：西班牙 Navajún 的黄铁矿以棱线极清晰的立方体
> 与立方体穿插连晶著称，秘鲁 Huanzala 又是另一样子。
> 结论：**可行，且现有引擎已经铺好了 80% 的地基**。本文档是实施方案，分期见 §5。

---

## 1. 为什么可行——现有能力盘点

| 需要 | 现有地基 | 缺口 |
|---|---|---|
| 单晶/双晶形态 | 12 矿物 × 30 外形 × 136 变体，双晶引擎（接触/贯穿/转变）成熟 | 无 |
| **多颗聚生** | 多晶体系统（上限 6 颗）：每颗独立 矿物/外形/掩码/位置/缩放/朝向，可拖动、可锁定整组 | 固定布局的"预设组合"未做（现在只有黄金角随机的「晶簇」按钮） |
| **跨矿物共生** | 附加晶体可以是不同矿物（黄铁矿旁边放萤石在引擎里天然合法） | 无 |
| 基质/围岩 | 基岩系统（石板/晶洞/木座）+ S1 的 3D 桌面 | "矿物基质"（白色 dolomite 基底、硫化物块状基底）未做，可用 3D 场景网格扩展 |
| 讲解文案 | 「认识它」四段科普 + 数据带 source/confidence | 产地级文案与来源未建 |

**关键判断**：产地晶习的本质 = "一组固定的晶体实例布局 + 一段讲解"。多晶体系统就是为这个准备的，
缺的只是（a）把布局存成数据、（b）一键载入、（c）产地级的文字与来源。

## 2. 数据模型（扩展 `spike/minerals.data.mjs`）

```js
// 矿物条目新增 localities 数组；每条 = 一个产地 + 一个或多个"晶习组合"
localities: [
  {
    id: "navajun",
    zh: "西班牙 · 拉里奥哈（Navajún）", en: "Navajún, La Rioja, Spain",
    // 组合怎么摆：instances 里每颗 = 现有多晶体系统的一个实例
    setup: {
      base: "none",                 // 基岩：none / slab / geode / wood / matrix（未来）
      bg: "paper",                  // 推荐场景
      instances: [                  // 主晶体之外最多 5 颗（含主晶体共 6）
        { mineralId: "pyrite", habitId: "cube", mask: 1, pos: [0.3, -0.2, 0], scale: 1.0, yaw: 12 },
        { mineralId: "pyrite", habitId: "cube", mask: 1, pos: [-0.5, 0.1, 0], scale: 0.6, yaw: 84 },
      ],
    },
    habitId: "cube",                // 主晶体用哪个外形
    text: {                         // 产地特征讲解（中英；机制 + 判别要点）
      zh: "白色白垩质泥灰岩里嵌着棱线锋利的立方体，直径可到 15 cm；立方体常两三颗互相穿插...",
      en: "...",
    },
    features: ["棱线极清晰", "穿插连晶", "白垩基质"],   // 关键词，供筛选
    source: "Mindat Navajún；Handbook of Mineralogy",   // ≥2 来源（沿用双晶的双来源纪律）
    confidence: "high",             // high / medium / pending（pending 不进正式构建）
  },
  // ...每矿物 2–4 个产地
]
```

**约定**：
- `instances` 描述的是"载入后的附加晶体 + 主晶体状态"，与现有 `state.extras` 结构一一对应，
  载入 = 重置 extras → 逐条 mkExtra → 覆写 pos/scale/yaw → rebuild。**零新引擎**。
- 聚生类型标注 `style: "single" | "penetration" | "parallel" | "cluster" | "druse" | "paragenesis"`，
  页面上作为分类徽章（形态分类与成因分开，沿用双晶数据的老纪律）。
- 每条带 `checked: "YYYY-MM"` 与双来源；核对协议与双晶一致，**核不完不进正式版**。

## 3. UI / 交互设计

- **入口**：左栏「矿物」面板每条矿物加一个「产地晶习 ›」链接；以及顶栏「数据」浮出面板里加同款入口。
- **矿物志页（全屏覆盖层，不是弹小窗）**：
  ```
  ┌──────────────────────────────────────────────────┐
  │ ← 返回   黄铁矿 Pyrite FeS₂ · 等轴 · m-3           │  头部：矿物名 + 返回
  ├────────────┬─────────────────────────────────────┤
  │ 产地列表    │  3D 视口（复用主视口的 GL 管线）        │
  │ ▸ 西班牙    │                                     │
  │ ▸ 秘鲁     │  下方：产地讲解（text）+ 特征标签      │
  │ ▸ 中国湖南  │  + [载入这套组合] [导出图鉴卡]         │
  └────────────┴─────────────────────────────────────┘
  ```
  - 左列选产地 → 右侧视口**直接载入该组合**（主晶体 + extras + 基岩 + 推荐场景），
    可以照常旋转/拖动/改配色——矿物志页不是死的图文页，是"预配置的live场景"。
  - 「载入这套组合」把当前配置带回主界面（就是 Mineral志 视口当前的状态，无缝）。
  - URL hash 深链：`#mineral=pyrite&loc=navajun`——file:// 下可用，方便分享与收藏。
  - 中英双语沿用全局约束 G1：缺 en 显式 null 并在构建报告列出。
- **主界面联动**：载入某产地后，HUD 显示"西班牙 Navajún 组合"徽章，一键清除回默认。

## 4. 内容工作流（先做谁、怎么核）

**首批 4 种矿物 × 2–3 产地（试点）**：
| 矿物 | 产地 | 组合要点 |
|---|---|---|
| 黄铁矿 | 西班牙 Navajún | 立方体 + 立方体穿插连晶（2–3 颗，yaw 错开 ~90°），白垩基质（先用 paper 场景） |
| 黄铁矿 | 秘鲁 Huanzala | 立方体+五角十二面体聚形单晶簇（3–4 颗群聚） |
| 石英 | 美国阿肯色 | 长柱状平行连生（2–3 根并排微错角度）+ 底岩 |
| 石英 | 瑞士/阿尔卑斯 | 短柱状 + 菱面体发育，单晶或双晶横卧 |
| 萤石 | 英国 Cumberland | 紫色立方体 + 方解石共生（跨矿物 instance） |
| 方解石 | 冰岛 | 冰洲石菱面体单晶（光学级透明） |

**核对协议**（沿用 §J）：形态描述 ≥2 独立来源（Mindat 产地页 / Handbook of Mineralogy /
产地专著）；几何（晶形、k 值）依旧由引擎从 (hkl) 算，产地页只存"哪些晶形 + 怎么摆"；
描述性文字标注来源；`confidence: pending` 不进正式构建。

**图片**：矿物志页可放 1 张参考照片（AI 生成或用户后续提供实拍），标注"示意"——
不冒充标本照（"理想形态"诚实原则）。

## 5. 分期

| 期 | 内容 | 验收 |
|---|---|---|
| **L1** | 数据 schema + 矿物志覆盖层 UI + 「载入组合」管线 + 黄铁矿/石英试点 4 条 | hash 深链可开；载入后 extras/基岩/场景与数据一致；双语键齐全 |
| **L2** | 首批 12 矿物全覆盖（每矿物 ≥2 产地）；产地筛选标签 | 每条有双来源与 confidence；构建门禁挡 pending |
| **L3** | 基质（matrix）3D 网格 + 晶洞（druse）微晶群（突破 6 颗上限：同矿物小晶体合并 draw call 或提高上限） | 萤石+方解石共生、druse 场景可渲染 |

**工作量感觉**：L1 ≈ 一轮（UI+管线是大头）；L2 主要是内容核对（慢工）；L3 需要动 GL 场景层（跟 S2/S3 场景建模共用能力）。

## 6. 与其他路线的关系

- 依赖 S2/S3 的场景能力（基质/晶洞是场景网格），建议 **L1/L2 先行**（不依赖），L3 与 S2 合并做。
- 矿物志的「导出图鉴卡」直接复用现有导出（多晶体导出已支持）。
- 这一条不进 MVP 路线图的既有里程碑，作为 M4b（扩 20 矿物）的并行内容线：**产地晶习数据天然是 M4b 新矿物的填写模板**（新矿物直接带 2 个产地条目录入）。
